# Receipt Download Fix Report

## Root Cause

Payment verification already finalized verified payments into paid invoice/receipt records and generated invoice PDF document metadata. The download path was the fragile part:

- `/api/v1/invoices/[id]/download` returned JSON containing a Supabase signed URL instead of returning the PDF.
- The service trusted `invoice.pdf_document_id` and `invoice.pdf_storage_path` without confirming the storage object existed or was a valid PDF.
- If the storage object was missing, stale, or corrupted, the app still produced a URL and the browser hit storage directly, causing 404s, blank/corrupt PDFs, missing headers, or inconsistent browser behavior.
- Browser download headers were controlled by storage, not the application.

## Fix Implemented

- Replaced the invoice download API response with an authenticated PDF stream.
- Kept all existing authorization checks:
  - Organization access is required.
  - Finance/admin roles must have hostel scope.
  - Residents can download only their own invoice/receipt.
- Added storage download and PDF signature validation before returning bytes.
- Added repair-on-download:
  - Missing PDF metadata/storage is regenerated from invoice context.
  - Corrupt or missing storage objects are force-regenerated and uploaded with `upsert`.
- Kept legacy signed URL generation, but it now validates/repairs the PDF first and signs with the admin storage client only after app authorization.
- Updated resident/admin clients to open the same-origin app download endpoint instead of Supabase storage URLs.
- Added hardened download headers:
  - `content-type: application/pdf`
  - `content-disposition: attachment`
  - `cache-control: private, no-store`
  - `x-content-type-options: nosniff`
  - `content-length`

## Before vs After

Before:
- Verified payment could have a receipt invoice record but still fail download if storage was stale/missing/corrupt.
- Download endpoint returned JSON with a storage signed URL.
- Browser behavior depended on Supabase storage headers.
- Missing/corrupt storage objects were not repaired during download.

After:
- Verified payment receipts are downloaded through the app after authorization.
- The app verifies or regenerates the receipt PDF before returning it.
- Browser receives a real PDF response with attachment headers.
- Residents remain limited to their own receipts.
- Admin access remains tenant and hostel scoped.
